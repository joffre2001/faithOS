# FaithOS mobile release guide

FaithOS now includes Capacitor projects for Android and iOS under `frontend/android` and `frontend/ios`.

## Before making a release

1. Deploy the Spring Boot API behind HTTPS.
2. Copy `frontend/.env.mobile.example` to `frontend/.env.mobile` and set `VITE_API_URL` to the public API URL ending in `/api`.
3. In the backend environment set:
   - `AUTH_COOKIE_SECURE=true`
   - `AUTH_COOKIE_SAME_SITE=None`
   - `CORS_ALLOWED_ORIGINS=https://app.faithos.local,capacitor://app.faithos.local`
4. Configure SMTP, the PIX key, database backups, and uploaded-file storage.
5. Replace the generated Capacitor placeholder icons and splash screens with approved FaithOS artwork before submission.

## Android / Google Play

Install Android Studio and its current supported Android SDK, then run from `frontend`:

```powershell
npm run android:open
```

In Android Studio, configure a private release signing key and build a signed Android App Bundle. Never commit the keystore or its passwords. Upload the `.aab` to Play Console, first through Internal testing.

The application ID is `com.obysoft.faithos`.

## iOS / App Store

iOS signing and archives require macOS, Xcode, an Apple Developer membership, and an App Store Connect record. On the Mac run from `frontend`:

```bash
npm ci
npm run ios:open
```

Select the FaithOS team and signing profile in Xcode, archive the `App` target, validate it, then upload it to App Store Connect and TestFlight.

## Required store information

- Privacy-policy URL and support URL
- Account-deletion instructions
- Phone and tablet screenshots
- App description, category, age rating, and contact details
- Google Play Data safety form
- Apple App Privacy answers
- Explanation that PIX is generated by FaithOS but settled by the member's bank

## Release checks

- Test login, logout, password reset, uploads, downloads, ministry chat, support email, and PIX on physical devices.
- Confirm CPF and emergency-contact data are shown only to authorized church staff.
- Confirm HTTPS and certificate validity; release builds must never use cleartext HTTP.
- Test accessibility font scaling, screen readers, keyboard focus, dark/light contrast, and small-screen layouts.
- Publish database backup, incident-response, retention, and account-deletion procedures.
